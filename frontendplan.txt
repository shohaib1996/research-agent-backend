## 🎯 Project Overview

### What You're Building

A modern, responsive web interface for your Agentic Research Assistant with:
- Real-time research capabilities
- Session history management
- Dark/light theme switching
- Responsive design (mobile + desktop)
- Professional UI with shadcn/ui components

### User Flow

```
User lands on homepage
    ↓
Sees input form + theme toggle
    ↓
Types research question
    ↓
Clicks "Research" button
    ↓
Sees loading state (skeleton/spinner)
    ↓
Receives comprehensive answer with:
    - Quality score badge
    - Iteration count
    - Research plan summary
    - Full answer (formatted)
    ↓
Can view history page
    ↓
Can click past sessions to view details
```

## 🛠️ Technology Stack Breakdown

### Core Technologies

**1. Next.js 14 (App Router)**
- **Why:** Server-side rendering, routing, API routes, optimization
- **What you'll use:** 
  - App Router for pages
  - Server components where possible
  - Client components for interactivity

**2. TypeScript**
- **Why:** Type safety, better DX, fewer bugs
- **What you'll use:**
  - Interface definitions for API responses
  - Type-safe props
  - Autocomplete in IDE

**3. Tailwind CSS**
- **Why:** Utility-first, fast styling, built into Next.js
- **What you'll use:**
  - Responsive design classes
  - Dark mode classes
  - Custom color variables

**4. shadcn/ui**
- **Why:** Beautiful, accessible components, customizable
- **What you'll use:**
  - Button, Card, Input, Textarea
  - Badge, Skeleton, Toast
  - Dropdown, Separator, Tabs

**5. Axios**
- **Why:** Better API handling than fetch, interceptors, timeout
- **What you'll use:**
  - API client instance
  - Request/response interceptors
  - Error handling

**6. next-themes**
- **Why:** Best dark mode solution for Next.js
- **What you'll use:**
  - Theme provider
  - Theme toggle hook
  - System preference detection

**7. Zustand (State Management)**
- **Why:** Simple, lightweight, better than Context API
- **What you'll use:**
  - Research state
  - Session history state
  - UI state (loading, errors)

**8. Additional Libraries**
- **lucide-react:** Icons
- **react-markdown:** Render markdown answers
- **date-fns:** Format dates nicely
- **sonner or react-hot-toast:** Better toast notifications

## 🧩 Component Architecture

### Component Hierarchy

```
App Layout
├── ThemeProvider (wraps everything)
├── Navbar
│   ├── Logo/Title
│   ├── Navigation Links
│   └── ThemeToggle
│
├── Home Page
│   ├── Header Section
│   ├── ResearchForm
│   │   ├── Textarea (question input)
│   │   └── Submit Button
│   ├── LoadingSkeleton (conditional)
│   └── ResearchResult (conditional)
│       ├── Quality Badge
│       ├── Iteration Badge
│       ├── Research Plan
│       └── Answer (Markdown)
│
└── History Page
    ├── Header Section
    ├── Filter/Search Bar (optional)
    └── Session List
        └── SessionCard (multiple)
            ├── Question Title
            ├── Quality Score
            ├── Date
            └── Answer Preview
```

### Component Design Principles

**1. Composition over Inheritance**
- Small, reusable components
- Each component does ONE thing well

**2. Container/Presentational Pattern**
- Smart components (data fetching)
- Dumb components (just display)

**3. Component Responsibilities**

**ResearchForm (Smart)**
- Handles form state
- Validation
- Calls API function
- Shows loading state
- Handles errors

**ResearchResult (Presentational)**
- Receives result as prop
- Displays data
- No logic, just rendering

**SessionCard (Presentational)**
- Receives session as prop
- Displays preview
- Click handler from parent

## 🔄 State Management Strategy

### Zustand Store Structure

**1. Research Store**
```
State:
- currentQuestion: string
- isLoading: boolean
- result: ResearchResponse | null
- error: string | null

Actions:
- setQuestion(q: string)
- startResearch(question: string)
- setResult(result: ResearchResponse)
- setError(error: string)
- reset()
```

**2. Session Store**
```
State:
- sessions: Session[]
- isLoading: boolean
- selectedSession: Session | null

Actions:
- fetchSessions()
- selectSession(id: string)
- clearSelection()
```

### When to Use Zustand vs Local State

**Use Zustand for:**
- Data shared across pages
- Research results (might show on multiple pages)
- Session history

**Use Local State (useState) for:**
- Form inputs
- UI toggles (dropdowns, modals)
- Component-specific data

## 🔌 API Integration Plan

### Axios Setup Strategy

**1. Create Base Instance**
- Base URL from environment variable
- Default headers (Content-Type: application/json)
- Timeout: 120 seconds (research takes time!)

**2. Request Interceptor**
- Add auth tokens (if needed later)
- Log requests (in development)

**3. Response Interceptor**
- Handle common errors
- Parse error messages
- Retry on network failure (optional)

**4. API Functions**

Create separate function for each endpoint:

**performResearch(question, useCache)**
- POST /api/research
- Returns: ResearchResponse
- Handles: Loading, errors, timeout

**getRecentSessions(limit)**
- GET /api/sessions/recent
- Returns: SessionsResponse
- Handles: Empty state

**getSession(sessionId)**
- GET /api/sessions/{id}
- Returns: SessionDetailResponse
- Handles: 404 not found

**checkHealth()**
- GET /
- Returns: health status
- Use for: Connection testing

### Error Handling Strategy

**Network Errors:**
- Show toast: "Connection failed. Check if backend is running."
- Offer retry button

**Timeout Errors:**
- Show toast: "Research taking too long. Please try again."
- Don't fail silently

**Validation Errors:**
- Show inline form errors
- Highlight input field

**Server Errors (500):**
- Show toast: "Server error. Please try again later."
- Log to console for debugging

## 🌓 Dark/Light Mode Strategy

### Implementation Plan

**1. Setup next-themes**
- Wrap app in ThemeProvider
- Enable system preference detection
- Prevent flash of wrong theme

**2. Create Theme Toggle**
- Dropdown with 3 options:
  - Light
  - Dark
  - System (auto)
- Smooth icon transition
- Position: Top right of navbar

**3. Customize Colors**

Define CSS variables for both themes:

**Light Theme:**
- Background: white
- Text: dark gray
- Cards: light gray
- Borders: subtle gray
- Primary: blue/purple
- Accent: lighter shade

**Dark Theme:**
- Background: very dark gray
- Text: light gray/white
- Cards: dark gray
- Borders: slightly lighter gray
- Primary: brighter blue/purple
- Accent: lighter shade

**4. Component Theming**

Each component should use theme-aware classes:
- `bg-background` not `bg-white`
- `text-foreground` not `text-black`
- `border-border` not `border-gray-300`

**5. Test Both Themes**
- Check all pages in both themes
- Verify contrast ratios (accessibility)
- Test smooth transitions

## ⚡ Performance Optimization

### Optimization Strategy

**1. Code Splitting**
- Dynamic imports for heavy components
- Load markdown renderer only when needed
- Lazy load history page

**2. Image Optimization**
- Use Next.js Image component
- Proper sizes and formats
- Lazy loading

**3. API Optimization**
- Cache API responses (axios-cache-adapter)
- Debounce search inputs
- Pagination for history (don't load 1000 sessions)

**4. Bundle Optimization**
- Tree-shaking unused code
- Minimize bundle size
- Analyze with next/bundle-analyzer

**5. Rendering Optimization**
- Use React.memo for expensive components
- useCallback for functions passed as props
- useMemo for expensive calculations

**6. Loading States**
- Show skeleton immediately
- Progressive loading (show parts as they load)
- Optimistic UI updates

## 🚀 Deployment Plan

### Deployment Strategy

**Platform: Vercel (Recommended)**

**Why Vercel:**
- Made by Next.js team
- Zero config deployment
- Automatic HTTPS
- Global CDN
- Free tier
- Environment variables
- Preview deployments

**Alternative: Netlify**
- Similar features
- Also free tier
- Easy setup

### Deployment Steps

**1. Prepare for Deployment**
- Test production build locally: `npm run build`
- Verify no errors
- Check environment variables

**2. Connect to Vercel**
- Create Vercel account
- Connect GitHub repository
- Auto-deploy on push to main

**3. Configure Environment Variables**
- Add NEXT_PUBLIC_API_URL in Vercel dashboard
- Point to your deployed backend URL

**4. Deploy**
- Push to GitHub
- Vercel auto-builds and deploys
- Get live URL (yourapp.vercel.app)

**5. Custom Domain (Optional)**
- Buy domain (Namecheap, Google Domains)
- Add to Vercel
- Configure DNS

**6. Post-Deployment**
- Test live site
- Check API connection
- Monitor errors (Vercel Analytics)

- Build MVP first
- Add features later
- Don't over-engineer
